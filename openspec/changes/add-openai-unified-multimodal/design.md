## Context

Agent 的工具、MCP、权限、技能和运行轨迹均依赖 Claude Agent SDK；不同 provider 目前都假定 Messages 协议。图像原件已有会话存储和专业 Agent 工作区物化，但输入仍强制经过独立 OCR。工作树存在默认关闭的证据实验，必须原样保留。

## Goals / Non-Goals

**Goals:** 原生 OpenAI Responses 请求；同一个选定模型处理文本、截图与工具结果；真实增量输出、工具往返、计量、取消和隔离；兼容原有 provider；本地 Docker 真实端到端测试。

**Non-Goals:** 替换全部现有 SDK 工具实现；生产部署；付费方式变更；提交凭据；改变已有实验开关。

## Decisions

1. 每次 OpenAI query 启动独立、仅绑定 loopback 的短生命周期协议桥，将 SDK Messages 转换为标准 Responses 请求，再转换回 SDK 消息/SSE。保留 SDK 工具循环与权限，不引入公开代理路由，不重写六套工具调度。每次运行使用独立随机本地认证令牌，OpenAI 密钥只由后端 HTTP 客户端使用。
2. provider 目录增加 `openai` 与显式协议字段。沿用现有主/备/BugFix 配置槽和密钥池，Admin 连通测试使用相同 Responses 协议。OpenAI 的 small/fast 与主模型固定一致。
3. 图像在 API 边界继续验证与安全存储。OpenAI 模式跳过 OCR；公共 query 包装器将工作区 manifest 中的原图加入首条用户消息。通用/设备会话也物化经服务端验证的附件；图片工具结果按多模态内容传回同一模型。无法加载图片时明确失败，不伪装识别成功。
4. 保留路由器原有提交边界：未产出真实模型内容前允许失败转移；产出内容或执行工具后不重放。桥的流式状态机处理文本、函数参数、终态、错误与 usage，连接取消时释放上游请求和监听 socket。
5. API Key 使用用户授权的独立本地专用 Key；只保存于受限本地文件/环境配置。测试栈使用独立端口、容器名和持久卷，保留现有实验容器及数据。

## Risks / Trade-offs

- SDK 上游协议演进 → 明确处理支持的内容与工具类型，未知类型报错；覆盖真实 SDK 工具往返。
- 流式事件顺序、截断或错误 → 状态机回归测试及真实 SSE 验收，不把失败当成功。
- 图片缺失或工作区路径逃逸 → 只读取 manifest 中的安全相对文件，限制 MIME、数量和大小；缺失明确报错。
- 辅助模型被旧配置覆盖 → OpenAI 模式固定统一模型，并覆盖后台保存配置的实际运行验证。
- 默认额度用尽 → 保持未绑定 API 支付方式和无自动充值，错误明确传播，不隐式切换付费备用端点。
